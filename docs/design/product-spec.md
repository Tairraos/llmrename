# 产品规格

状态：草稿（工作区）。本文定义 llmrename 的可验收行为，随实现演进。

## 1. 目标

LLM 视觉模型驱动、本地优先、对非技术用户友好的**图片批量重命名工具**。

用户流程（单次使用）：

1. 打开应用，看到「模型配置」「模板配置」「资产库」「预览与执行」四个区块。
2. 在模型配置里填入端点 / API Key / 模型名（可选用默认 OpenAI gpt-4o）。
3. 在模板框输入类似 `{人物}_{场景}_{日夜}` 的重命名模板（字段名支持中文）。
4. 选择一个图片目录作为资产库。
5. 点击「扫描」：列出全部图片，预览区按当前模板给出**猜测**的新文件名。
6. 点击「执行重命名」：对每张图片调用视觉模型提取要素 → 组装新名 → 改名，并把成功/失败逐条写入日志。

## 2. 非目标（当前版本不做）

- 不改动图片内容（不压缩、不转码、不写入 EXIF）。
- 不做目录结构迁移（仅重命名文件，不移动）。
- 不做多模型同时执行 / 任务队列后台常驻。
- 不做云服务端（密钥仅存本机配置）。
- 不做撤销（依赖系统回收站级别的自我风控，暂不实现）。

## 3. 用户故事与验收标准

### US-1 配置模型
- 当：用户填写 `base_url`、`api_key`、`model`，点保存
- 则：配置写入应用数据目录 `config.json`，重开应用后仍生效
- 验收：切换主窗口或重开应用后表单回填保存值。

### US-2 配置模板
- 当：用户在模板框输入 `{人物}_{场景}_{日夜}` 或点「推荐变量」chip 插入
- 则：「当前模板字段」自动列出各字段的示例值（人物→`woman`、日夜→`night` 等，基于字段名猜类别）
- 验收：字段列表随模板实时更新（输入即更新）。

### US-3 扫描资产库
- 当：用户选择目录 → 点「扫描」
- 则：按 `options.extensions` 过滤（默认 jpg/jpeg/png/webp/gif/bmp/tiff），按文件名自然排序，展示相对路径、大小、修改时间、当前文件名、猜测新名
- 验收：结果表格行数与目录内匹配文件数一致；无匹配时给出「未找到图片」提示而非报错。

### US-4 执行重命名（核心）
- 当：用户勾选行 → 点「执行」
- 则：对每张图调用视觉模型提取字段 → 组装 `base` → 校验后缀/黑名单 → 冲突时追加 `_2/_3` → 执行 `fs::rename` → 每个文件写一条日志
- 验收：
  - 模板渲染后文件名不含 `{}` 残留；
  - 目标名与同批其他目标名冲突时自动去重；
  - 目标名与黑名单词命中或后缀不在允许列表时，该文件标记 `skipped` 并记日志，不中断整体；
  - 真实提取失败（模型报错/超时/返回非法 JSON）时，该文件标记 `failed` 并记日志，继续处理下一张；
  - 全部结束后日志面板出现本次全部条目（N 成功 / M 失败）。

### US-5 查看日志
- 当：用户在日志面板点「打开日志目录」
- 则：系统文件管理器打开应用数据目录
- 验收：能看到 `rename_log.jsonl`，每行 JSON 含文件名、目标名、状态、要素快照、时间。

## 4. 数据模型（摘要，细节在架构/类型内）

- `ModelConfig { base_url, api_key, model, timeout_secs }`
- `TemplateConfig { pattern, fields }`
- `RenameOptions { extensions, blacklist, allowed_suffixes }`
- `LogEntry { ts, status, asset, target, fields, base, error }`

## 5. 错误体验

- 表单错误就地提示（红色小字 + 输入框边框）。
- 执行错误逐条进日志 + 汇总弹层显示「N 成功 / M 失败 / K 跳过」。
- 所有错误文案给修复提示（如「检查 API Key」「确认目录存在」）。

## 6. 开放问题

- 配置是否允许「每目录独立模板」？当前仅全局一份模板。
- 字段类别猜测表（date/time/camera/scene/…）是否需要用户可编辑？暂做内置列表。
- 是否需要「先复制到新名再删原名」的原子模式？当前直接用 rename。
