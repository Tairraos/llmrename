# 产品规格

状态：已随 v1.0.x 实现对齐（2026-10-02 校订）。本文定义 llmrename 的可验收行为，随实现演进。

## 1. 目标

LLM 视觉模型驱动、本地优先、对非技术用户友好的**图片批量重命名工具**。

用户流程（单次使用）：

1. 打开应用，把图片文件或**整个文件夹**拖进窗口（递归收集，子目录文件以相对路径提示）。
2. 在「模型设置」里填入端点 / API Key / 模型名（默认 OpenAI gpt-4o，兼容任意 Chat Completions 端点）。
3. 在「模板设置」里输入类似 `{人物}-{场景}-{日夜}` 的模板（字段名支持中文；推荐字段点击加入/再点移除；`{智能}` 为独占字段——完全由模型起一个 ≤12 汉字的中文文件名）。
4. 勾选要解析的行，点「解析改名」：视觉模型**逐张**解析，每张完成即更新对应列表行（不等全部完成）；调试台实时回显模型输出。可在「用户提示词」框补充要求随解析发送。
5. 目标名可手动微调、正则批量预览改名、行级 ↶/↷ 回溯；点「开始重命名」执行，写入 JSONL 日志。

## 2. 非目标（当前版本不做）

- 不改动图片内容（不压缩、不转码、不写入 EXIF）。
- 不做目录结构迁移（仅重命名文件，不移动）。
- 不做多模型同时执行 / 任务队列后台常驻。
- 不做云服务端（密钥仅存本机配置）。
- 撤销/重做为应用内内存态（每文件最多 10 条历史，退出即清），不做跨会话持久化。

## 3. 用户故事与验收标准

### US-1 配置模型
- 当：用户填写 `base_url`、`api_key`、`model`、超时，点保存
- 则：配置写入应用数据目录 `config.json`，重开应用后仍生效；「拉取」按钮可从端点拉取模型列表
- 验收：重开应用后表单回填保存值。

### US-2 配置模板
- 当：用户在模板框输入 `{人物}-{场景}-{日夜}`，或点推荐字段 chip（点击加入、再点移除；`{智能}` 点击后模板只留它、再点恢复原模板）
- 则：「当前模板字段」自动列出各字段与示例值（输入即更新）；示例说明只显示「示例：xxx.jpg」
- 验收：字段列表随模板实时更新；{智能} 独占与恢复行为正确。

### US-3 添加文件
- 当：用户拖入文件/文件夹（或点「选择图片 / 选择文件夹」）
- 则：递归收集匹配扩展名的文件（默认 jpg/jpeg/png/webp/gif/bmp/tiff），去重、按文件名自然排序；当前文件名 hover 提示文件名 + 相对拖入根目录的路径
- 验收：列表行数与收集数一致；子目录文件 title 第二行显示相对路径；点击表头「当前文件名」可正/倒序排序，勾选与已填目标名随行走。

### US-4 解析改名（AI 填充，核心）
- 当：用户勾选行 → 点「解析改名」
- 则：逐张调用视觉模型（提示词 = 字段名 + 各自提取指南 [+ 用户提示词]，不含文件名与模板）；每张完成：
  - 列表对应行**立即**显示生成目标名（不等全部完成），行级历史提交（可 ↶ 回溯）；
  - 调试台回显流式输出与 `[i/N] ✓/✗` 状态；
  - 单张失败（网络/超时/非法 JSON）不影响其余文件，失败行保持原名；
  - 「暂停解析」在文件边界停下，「继续解析」从剩余文件恢复。
- 验收：模型输出被寒暄/围栏/单引号包裹时仍能正确解析（多级容错）；状态栏不显示模型状态（只进调试台）。

### US-5 正则改名（确定性批量）
- 当：用户点「正则改名」弹出小对话框，填写查找/替换（只作用于文件名，扩展名不参与）
- 则：输入实时预览——命中行显示替换结果（只读）与高亮；「查找」逐个定位命中行（滚动 + 醒目标记，点其他位置消失）；「选中」勾选全部命中行；关闭弹层即**采用**预览值（落定为可编辑目标名并清空正则字段）
- 验收：非法正则红字提示；预览不进行级历史；执行时以落定值改名；执行成功后方案消费清空。

### US-6 执行重命名
- 当：用户点「开始重命名」
- 则：只处理「勾选 且 目标名 ≠ 当前名」的行；目标名校验（空/路径分隔符/扩展名白名单）；目标已存在时自动追加序号（`名称 1.ext` 起顺序尝试）；每条结果写 JSONL 日志
- 验收：成功行自动取消勾选、当前名更新、目标列清空显示；失败/跳过行保持原名与勾选；同名批量得到连续序号；改回旧名可用行级 ↶ 后再次执行。

### US-7 查看日志
- 当：用户打开「操作日志」
- 则：最近 200 条（成功/失败/跳过）倒序展示，可打开日志目录
- 验收：`rename_log.jsonl` 每行 JSON 含时间、文件名、目标名、状态、错误。

## 4. 数据模型（摘要，细节在架构/类型内）

- `ModelConfig { base_url, api_key, model, timeout_secs }`
- `TemplateConfig { pattern }`
- `RenameOptions { extensions, blacklist, allowed_suffixes }`（blacklist 校验未实现，见执行计划技术债）
- `AssetEntry { path, filename, relative_path, size_bytes, modified_secs }`
- `LogEntry { ts, status, asset, target, error }`

## 5. 错误体验

- 表单/弹层错误就地提示（红色小字）。
- 执行错误逐条进日志 + 汇总提示「成功 N · 失败 M · 跳过 K」。
- 所有错误文案给修复提示（如「检查 API Key / 配额 / 模型名」）。
- 解析失败附模型响应片段与 serde 详情，便于判断是提示词问题还是服务问题。

## 6. 开放问题

- 配置是否允许「每目录独立模板」？当前仅全局一份模板。
- options.blacklist（新文件名禁用词）已建模未接线：应在 rename_explicit 校验并标 skipped。
- 是否需要「先复制到新名再删原名」的原子模式？当前直接用 rename。
